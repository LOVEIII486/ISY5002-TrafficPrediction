# 历史 PeMS08 结果补充、数据核对与优化建议

整理日期：2026-10-12。只读取已有产物和代码，没有重新训练、推理或运行测试集评估。

## 1. 结论

- **PEMS08 与 PEMSD8 是同一个研究基准的原始格式和 LibCity 格式。** LibCity 官方 `pemsd8.py` 明确从 ASTGCN 的 `PEMS08.npz` 转换得到 `PEMSD8.dyna`。
- **尚不能证明新仓库历史训练使用的数据与旧文件逐值一致。** 新仓库只附带 `run.json`，没有训练时的数据包和校验和。不能把同一基准名称当作数据内容审计通过。
- **两组结果不能合并排名。** 输入、划分、优化器设置、训练预算、课程学习和指标汇总方式都有区别。
- 本次补入旧实验的 4 个已完成模型与 3 个朴素基线；GWNET 只保留中断前的曲线，AGCRN、STGCN 没有该次正式实验结果。不能把 smoke 或其他中断试跑补成完整结果。

新资料放在 `results/imported/pems08_cpu10_seed0/`，原有 `results/forecast/` 和 demo 的默认实验选择不变。

## 2. 数据集是不是一样

依据：[LibCity 官方转换器](https://github.com/LibCity/Bigscity-LibCity-Datasets/blob/master/pemsd8.py)。

| 检查项 | 旧实验 | 新仓库 | 结论 |
|---|---|---|---|
| 名称 | PEMS08 | PEMSD8 | 同一基准的命名与格式差异 |
| 来源 | ASTGCN 仓库原始 NPZ | LibCity 分发的原子格式 | 官方转换器说明了来源关系 |
| 节点 / 采样 | 170 / 5 分钟 | 注册信息为 170 / 5 分钟 | 元数据一致 |
| 时间范围 | 2016-07-01 至 2016-08-31，17,856 点 | 官方转换器使用相同区间和形状 | 转换规范一致，历史训练文件未提供 |
| 字段 | flow / occupancy / speed | flow / occupancy / speed | 本次跨实验核对只比较 flow |
| 道路边 | CSV 295 行，277 个唯一有向点对 | 注册信息 277 条边 | 官方转换器去重；二值邻接下重复行不增加边权 |
| 文件内容 | 原始 NPZ 和 CSV 的 SHA256 已重新核对 | 历史 `run.json` 不记录数据哈希 | **逐值一致性未验证** |
| 测试窗口 | 3,561 个；目标窗口不跨分界；末批不补齐 | 使用 LibCity 的划分和补齐，历史记录未保存样本索引 | **测试样本一致性未验证** |

旧实验原始文件 SHA256：

```text
pems08.npz  e1d03ce74e9fb79149e6e7c37c680214822c4a285baa2f42278cacabcd25c075
distance.csv  859d68e7583ed4e6016588eaaca494d3ece286dae361614c5c1833017f87eaa7
```

完整机器可读记录见 `dataset_audit.json`。旧 CSV 的重复边与新库的双向化开关是两件事：即使唯一边集合相同，各模型使用的最终邻接矩阵仍需单独记录。

如果拿到新实验训练时的 `datasets/libcity/PEMSD8/`，应按 `(time, entity_id)` 对齐全部三个字段，比较数值、节点顺序、时间范围和唯一边集合，再核对测试目标时间索引。NPZ 和 CSV 编码不同，不能直接要求两种格式的文件哈希相同。当前无需重新训练即可完成这些数据核对，但缺少新实验的原始文件。

## 3. 实验条件差异

| 项目 | 旧实验：本次导入 | 新仓库已有实验 |
|---|---|---|
| 目标 | 仅 traffic_flow | flow、occupancy、speed 分别训练，也有联合实验 |
| 输入 / 输出 | 12 → 12，过去 60 分钟预测未来 60 分钟 | 相同 |
| 训练 / 验证 / 测试 | 60% / 20% / 20%；按原始时间切分，目标窗口不跨界 | 公共协议 70% / 10% / 20%；由 LibCity 构造窗口和划分 |
| 实际输入通道 | 所有模型只有 flow 1 通道 | FNN、STGCN 为 1；MTGNN 为 flow + 时刻 2；MultiHeadSTGCN 为 flow + 时刻 + 星期 9 |
| 预算 / 批次 / 早停耐心 | 10 轮 / 8 / 10 | 最多 100 轮 / 64 / 30 |
| 随机种子 / 设备 | seed 0 / CPU | 基线 seed 0 / CUDA；自定义模型另有多种子记录 |
| 训练实现 | LibCity 模型类 + 自定义统一 PyTorch 循环 | LibCity 模型或自定义类 + LibCity 执行器 |
| 优化器及调度 | 所有模型实际 Adam，lr 0.001，无调度、无 weight decay | 各模型的 LibCity 设置；自定义模型 RMSprop + StepLR |
| MTGNN | 课程学习关闭 | step_size1=627 的课程学习设置 |
| 训练损失 | 标准化空间中排除零目标的 MAE | 各模型 calculate_loss；自定义模型默认还除以每批目标平均量级 |
| 标准化 | 仅训练时间戳拟合 mean/std | standard；历史记录不含拟合统计和样本范围，需数据和加载器进一步核对 |
| 掩码 | abs(truth) > 1e-6 | abs(truth) >= 1e-4，且排除无效值 |
| 全时段指标 | 所有样本 × 节点 × 12 步合并计算 | 各步分别计算，再取 12 步算术平均 |
| 最后一个批次 | 不补齐 | `pad_with_last_sample=true`；历史记录未说明评估后是否去掉补齐样本 |

特别注意：旧 `architecture_config.json` 的 `add_time_in_day=true`、`learning_rate=0.01`、`lr_decay=true` 等可能是模型配置的默认值。旧循环不经过 LibCity 数据加载器/执行器，实际执行由 `run_config.json` 和 `source_snapshot/legacy_runner.py` 决定。例如旧 GRU/LSTM 实际没有时间特征、实际学习率为 0.001，也没有调度器。

同为“12 步平均”并不代表指标相同：旧 RMSE 是先合并所有误差再开方，新 RMSE 是每步开方后取平均；MAE/MAPE 在每步有效点数不同时也不完全等价。没有两组原始预测和相同测试索引时，不能直接换算这些汇总值。

## 4. 旧实验：已完成的结果

此表是旧协议内部的对比。数值来自原始 `comparison.csv`，不是本次重新评估。

| 方法 | 全 12 步 masked MAE | pooled masked RMSE | masked MAPE | 第 30 分钟 MAE | 第 60 分钟 MAE |
|---|---:|---:|---:|---:|---:|
| persistence（最后值保持） | 25.2862 | 38.6467 | 15.64% | 24.2576 | 34.6973 |
| moving_average（过去 12 点均值） | 32.0175 | 47.4659 | 20.30% | 31.0461 | 42.8455 |
| seasonal_naive（前一天同一时刻） | 36.5522 | 60.7646 | 24.58% | 36.5600 | 36.5100 |
| FNN | 21.3026 | 32.9304 | 14.10% | 20.6259 | 28.3396 |
| GRU | 21.8542 | 34.5356 | 13.70% | 21.7267 | 22.7586 |
| LSTM | 22.3033 | 35.6113 | 14.12% | 22.2026 | 23.1726 |
| MTGNN | **15.9992** | **24.9696** | **10.51%** | **15.9916** | **17.9684** |

- 旧协议下，MTGNN 在上述各项表现最好；这是该次 10 轮实验的结果，不是这些模型的充分收敛结论。
- GRU 的平均 MAE 略高于 FNN，但 MAPE 更低；第 60 分钟 MAE 也更低。应按预测时段和指标解释，不能只看总平均就认定 GRU 全面更差。
- 朴素基线成本低，适合补入之后统一协议的正式对照，但这里的数值仍属于旧测试窗口。

## 6. 优先优化的地方

### P0：先把实验条件和记录补完整

1. **为数据及样本建立可追溯记录。** 保存原始文件 SHA256、节点顺序、最终邻接哈希、测试目标时间索引和 scaler 拟合范围。确认两份实际数据后，再建立正式对比表。
2. **区分论文复现与受控模型对照。** 现有三个基线可继续按原配置复现；若论证自定义结构更好，应另建一组所有模型都有相同时刻/星期输入、相同划分和指标的实验。目前自定义模型 9 通道、MTGNN 2 通道，提升不能全部归功于结构。为 MTGNN/FNN/STGCN 加同样时间特征的实验尤其有价值。
3. **修复多模型汇总的统计含义。** `run_benchmark.write_summary()` 把本次所有模型的 records 一起传给 `metrics.aggregate()`，后者只按目标/指标聚合，未按模型分组。一次跑多个模型会把不同模型当成重复实验计算均值/标准差。应按数据集、目标、模型和实际配置分组后再聚合种子。
4. **保存实际配置与权重。** `train.run()` 的 effective 缺少 head_mode、spatial_mode、direct_multi_step、scale_aware_loss、optimizer、scheduler、课程学习进度等；某些变体身份只在文档里。应保存完整解析后配置、代码/LibCity 版本、实际完成轮数、最佳轮次和最终任务步数，并导出可加载的 checkpoint。当前模型权重和预测数组缺失，不能直接恢复推理或重算统一指标。
5. **统一指标及批次处理。** 同时记录 pooled 与逐步平均的定义、掩码阈值、有效样本数量；排除评估补齐样本。不能只修改旧 CSV 的表头来让数值看起来同口径。

### P1：有依据的模型实验方向

1. **补 GRU/LSTM 的正式实验。** 现有旧结果证明实现曾完成训练和测试，但预算较短、无时间特征。先接入新协议、配同样的输入和验证选模规则，再比较 30/60 分钟误差。不要使用旧 architecture_config 中未执行的学习率/调度设置。
2. **补 AGCRN / GWNET 图模型。** AGCRN 尚无正式旧结果；GWNET 的旧兼容修改是模块内 `np.int→int` 和二维卷积替换，见源码快照。若接入新库，应单独记录兼容修改，不能把旧 GWNET 验证曲线当作 baseline 分数。
3. **检查单目标 scale_aware_loss。** `MultiHeadSTGCN.calculate_loss()` 在单目标下也默认除以当前批次真值平均绝对值，等于让不同流量批次获得不同权重；不只是多目标单位对齐。可受控比较开/关，判断对 MAE/MAPE 的影响。多目标归一化尺度若重做，应考虑只从训练集估计固定尺度。
4. **为 MTGNN 记录课程进度。** 固定 step_size1=627 依赖 batch 数和训练预算，改变 batch/划分或提前停止后不一定覆盖全部 12 个任务步。正式比较应记录实际训练到的 task_level，而不只检查配置值。
5. **补同配置多种子对照。** MTGNN 等基线目前只有 seed 0，自定义模型已有部分多种子。相同种子集合下比较均值和标准差，才能判断流量上约 0.17% 的差异是否稳定；不要拿 5 次平均与单次最优值比较。

### P2：与课题目标有关的后续工作

- METR_LA 可以检验速度预测的跨数据集表现，但它没有 PeMS08 的三个目标，不能混在同一排名中。
- 公开 PeMS 数据提供传感器测量真值，能支撑预测评估；它不能证明 LTA 图片中的车辆框或拥堵等级正确。YOLO 检测的权威标注评估仍需独立补充。
- 若最终需要拥堵等级，应明确用速度/占有率如何生成等级及如何验证；当前连续值预测结果不能直接写成拥堵分类准确率。

## 7. 文件与复查方式

- `run_config.json`、`comparison.csv`：旧实验原始记录，逐字节保留。
- `models/*/training_history.csv` 与 `architecture_config.json`：完成及中断模型的记录。
- `dataset_metadata.json`、`dataset_audit.json`：原始数据指纹和跨实验核对边界。
- `import_manifest.json`：来源路径及每个原始导入文件的 SHA256；旧实验当时未提交，使用文件哈希追溯。
- `source_snapshot/`：实际旧循环和转换脚本的证据快照，**不是新仓库可直接运行的入口**。
- `history_summary.json`：已记录轮数、验证集最佳轮次和完成状态。
- `reference_comparison.csv`：带协议组的并列表，禁止跨组排名。
- `scripts/import_pems08_results.py`：标准库导入工具，只读取记录/文件校验和，不加载模型。已有导入目录时拒绝覆盖。

本次没有修改训练逻辑、补跑实验或重新计算测试集指标。P0/P1 是后续建议，尚未实施；本次的数据核对限于旧文件校验、来源转换关系和新仓库已记录的元数据。
